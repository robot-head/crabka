# Gres SQL-Parity Program — design

**Date:** 2026-07-09
**Status:** Approved
**Type:** Program decomposition (the chapter-roadmap genre). Orders "finish all SQL language support" — full PostgreSQL 18 SQL-surface parity for the Gres engine — into dependency-ordered waves across six tracks, with milestone gates, a per-command compatibility matrix, and the standing per-cycle rules. This supersedes and absorbs the [G-6 design](2026-07-09-crabka-gres-g6-fdw-sql-breadth-design.md)'s SQL-breadth track (G-6's FDW items are untouched); each wave remains its own design cycle under the chapter's process.

## Context — the verified gap, and the two findings that order everything

The compatibility sweep measured the engine's surface against the parser/executor source, and this program's grounding diffed the wave map against **all 190 commands in the PostgreSQL 18 reference** plus the PG16–18 language-feature surface. Two findings reorder intuition:

1. **Extended-protocol parameters do not execute.** The vendored pgwire's Bind *discards* parameter values, Execute ignores `max_rows` and re-runs raw SQL, there is no `PortalSuspended`, and the executor rejects `Expr::Param` outright. Every real driver and ORM speaks the extended protocol with `$n` parameters — so client compatibility fails before any missing type or DDL is reached. Parameter execution, plus the one-time widening of the 3-method `pgwire::engine::Session` trait (which every hard wave — COPY, cursors, NOTIFY — would otherwise each pay), is therefore **wave F-0**, ahead of everything.
2. **Session/GUC machinery is the largest structural omission.** `SET`/`SET LOCAL`/`RESET`/`SHOW` beyond the donor's GUC handful, `pg_settings`, `current_setting()`/`set_config()` — issued by essentially every driver at connect — form **wave F-1**.

The engine-side seam assessment sized the hard waves honestly: COPY is absent at all four layers but the seams are clean (the executor feed's chunked-commit semantics is the one real design); LISTEN/NOTIFY needs no restructuring (a `select!` at the session loop's idle read + an Engine-level bus) but is all-new code; SQL cursors reuse *new* portal machinery, not existing (materialized-result + position is sound and cheap given the engine materializes everything); SAVEPOINT's smallest sound design is **sub-xids as first-class xids** (other-transaction visibility then works unchanged; lock-holder model and own-visibility set change); SSI hooks cleanly into the two scan funnels with relation-granularity SIREAD locks as the truthful start (row-granularity pays off only once index scans exist); pg_catalog needs **no view mechanism** (the `ForeignScanner` seam already proves synthesized relations flow through joins/subqueries) — its long tail is client-driven, not architectural.

## Design Goals

- **Every one of the 190 commands answered:** implemented, mapped-with-documented-semantics, errors-with-notice matching stock PostgreSQL defaults, or a stated non-goal — tracked in a per-command **compatibility matrix** (`docs/PG_COMPAT_MATRIX.md`, the KIP_MATRIX idiom) that CI keeps honest.
- **Client reality first:** milestones are defined by what working software needs (drivers → pgbench → psql → ORMs/migrations), not by feature-family completeness.
- **The quirk is the spec:** the donor's north star carries over verbatim — match PostgreSQL's observable behavior including its quirks, oracle-differentially, with deviations only as documented, scoped non-goals.
- **Distributed and pooled semantics are part of every wave:** no feature ships without its sharded/ts-table story and its transaction-pooling story stated and tested.

## The explicit decisions (absence was the bug; any answer beats none)

- **SQL-level 2PC** (`PREPARE TRANSACTION`/`COMMIT PREPARED`/`ROLLBACK PREPARED`): match stock PostgreSQL's *default* — error 55000 "prepared transactions are disabled" (`max_prepared_transactions=0` is the stock default, so this IS the compatible behavior). A future wave may back it with the G-7 txn layer; not promised.
- **Databases:** one logical database per tenant — the tenant *is* the database (the product's unit). `current_database()` returns the tenant's database name; `CREATE/DROP/ALTER DATABASE` return a documented error pointing at tenant provisioning. Multiple logical databases per tenant is a named non-goal (schemas — D7 — are the namespace mechanism).
- **Large objects** (`lo_*`, `ALTER LARGE OBJECT`): non-goal with reason — `bytea` covers the storage need; JDBC BLOB users are documented to it.
- **`CREATE EXTENSION`:** the *statement* is supported with a whitelist of built-in shims (natively implemented function sets — e.g. `pgcrypto`-subset, `uuid-ossp`-compat via `uuidv7()`/`gen_random_uuid()`, `citext` with T-track collation machinery); unknown extensions get the stock PG error. Loading code remains the definitional non-goal.
- **C-bound object kinds — named non-goals:** `OPERATOR [CLASS|FAMILY]`, `ACCESS METHOD`, `CONVERSION` (UTF-8-only server), `TRANSFORM`, `LANGUAGE` (built-ins only: `sql`, `plpgsql`), `RULE` (legacy rewrite system), `SECURITY LABEL`, `LOAD`, `TEXT SEARCH PARSER/TEMPLATE` (though `TEXT SEARCH CONFIGURATION/DICTIONARY` are SQL-level → T7). `CREATE CAST`/`CREATE AGGREGATE` over SQL/PLpgSQL functions are implementable without C → **P6 stretch**, not non-goals. Event triggers → **P4 stretch** (stock error until then).
- **Tablespaces, publications/subscriptions (all variants), physical-replication SQL:** non-goals as the chapter already stated; P1 ships `pg_replication_*`/`pg_tablespace` catalog stubs so introspection tools don't trip.

## The wave map

Six tracks; waves within a track are ordered, tracks parallelize. Every wave = one design cycle (own spec, corpus growth, ratchet, matrix update). Contents below are exhaustive relative to the PG18 diff — items in *italics* are the grounding's additions to the original draft.

**Track F — foundations (strictly first):**
- **F-0 Extended-protocol reality:** `Session` trait v2 (parse/bind/execute-with-params, portal objects, `max_rows` + `PortalSuspended`, reserved COPY/notification variants — the one-time widening); `Expr::Param` binding + type inference; extended-protocol conformance leg (the corpus re-run through prepared statements with parameters).
- **F-1 Session/GUC machinery:** SET/SET LOCAL/RESET [ALL]/SHOW over a real parameter registry (transactional semantics preserved), `pg_settings`, `current_setting()`/`set_config()`, *`DISCARD`*, *`SET TRANSACTION` modes syntax (isolation wiring lands with S5)*.
- **F-2 pg_catalog:** system-relation scanner over the catalog (ForeignScanner pattern; no views needed), schema-qualified name parsing, stable OIDs, the catalog function set (`format_type`, `pg_table_is_visible`, `::regclass`, `current_schema()`, `version()`, `pg_typeof`, …), driven by what `psql \d`, sqlx, and common ORMs actually emit. (`information_schema` follows D5's views as **P1b**.)

**Track T — types (parallel after F-0):** **T1** int2/float4/varchar(n)/char(n) with typmod rules; **T2** uuid (+ `gen_random_uuid()`, *PG18 `uuidv7()`*); **T3** json/jsonb — operators, function set, jsonpath, *the SQL/JSON standard surface: `JSON_TABLE`, `JSON_EXISTS/QUERY/VALUE`, constructors/aggregates, `IS JSON`*; **T4** arrays — type system, subscripts/slices, `ANY/ALL`, `unnest`, array functions/aggregates; **T5** enums (*incl. `ALTER TYPE ADD VALUE`*), domains (*`ALTER DOMAIN`*), composites, range/multirange types; **T6** long-tail types: inet/cidr/macaddr, bit strings, money, timetz, geometric, xml (*or an explicit xml demotion decision — `XMLTABLE` scoped here*); **T7** full-text: tsvector/tsquery, functions, *`TEXT SEARCH CONFIGURATION/DICTIONARY` DDL* (seqscan-honest until GIN-class indexing, stated); **T8 collations:** `COLLATE`, `CREATE/ALTER/DROP COLLATION` over a pure-Rust ICU (icu4x) decision.
**Track D — DDL/storage (after F-0; D1 first overall after F-track):** **D1** constraints — SP41 port (NOT NULL/DEFAULT/CHECK/UNIQUE/PK) *+ GENERATED columns (STORED and PG18 VIRTUAL), `NULLS NOT DISTINCT`*; **D2** secondary indexes — CREATE/*ALTER/DROP* INDEX, partial/expression/multicolumn, access paths (the deepest cut; multi-slice); **D3** sequences — CREATE/*ALTER/DROP* SEQUENCE, nextval/currval/setval/lastval, SERIAL/IDENTITY (sharded-table story: interval/block allocation per the G-9 TSO idiom); **D4** ALTER TABLE family, TRUNCATE, COMMENT (*on every supported object kind*), *`CASCADE`/`RESTRICT` + `IF [NOT] EXISTS` as cross-cutting rules*; **D5** views + materialized views *+ `REFRESH MATERIALIZED VIEW [CONCURRENTLY]`* (→ unlocks P1b information_schema); **D6** FOREIGN KEY + referential actions, *DEFERRABLE + `SET CONSTRAINTS`*, *explicit dispositions: exclusion constraints (needs T5 ranges — scoped decision in-cycle), PG18 temporal `WITHOUT OVERLAPS`/`PERIOD` (deferred item, named)*; **D7** schemas (CREATE/ALTER/DROP, search_path via F-1), TEMPORARY tables, **declarative partitioning mapped onto native sharding** (`PARTITION BY RANGE/HASH` as sugar over G-8/G-9c machinery — its own coupled design cycle); **D8** RLS (CREATE/ALTER/DROP POLICY) + roles/privileges — GRANT/REVOKE, CREATE/ALTER/DROP ROLE (*+ USER/GROUP synonyms, `ALTER DEFAULT PRIVILEGES`, `DROP OWNED`/`REASSIGN OWNED`, `SET ROLE`/`SESSION AUTHORIZATION`*).
**Track Q — queries/DML (after F-0):** **Q1** statement completeness — INSERT…SELECT, RETURNING (*+ PG18 OLD/NEW*), ON CONFLICT (after D1/D2), UPDATE…FROM, DELETE…USING, data-modifying CTEs, MERGE (*+ PG17 `NOT MATCHED BY SOURCE`, MERGE…RETURNING*), *CREATE TABLE AS / SELECT INTO, standalone VALUES / `TABLE name`*; **Q2** window functions — OVER, frames, named windows, the window-function set; **Q3** SELECT completeness — DISTINCT ON, LATERAL, SRFs-in-FROM (*`WITH ORDINALITY`, `ROWS FROM`*), GROUPING SETS/ROLLUP/CUBE, FETCH FIRST (*`WITH TIES`*), NULLS FIRST/LAST, LIMIT expressions, recursive CTEs (*+ SEARCH/CYCLE, `MATERIALIZED` hints*), *row-locking completeness: FOR NO KEY UPDATE/KEY SHARE, NOWAIT, `SKIP LOCKED`*, *TABLESAMPLE*; **Q4** expression/operator/aggregate completeness — IS DISTINCT FROM, AT TIME ZONE, `%`/`^`/bitwise, regex `~`/SIMILAR TO, ROW(), ARRAY[] (with T4), COLLATE (with T8), string_agg/array_agg/bool_and/or/statistical aggregates, FILTER, WITHIN GROUP/ordered-set; **Q5** COPY — both directions, the wire subprotocol, the chunked-commit ingest design (the cycle's crux, named).
**Track S — sessions/transactions (after F-0):** **S1** SAVEPOINT/ROLLBACK TO/RELEASE via **sub-xids as first-class xids** (per the seam assessment; lock-holder set + own-visibility set changes; *BEGIN/START TRANSACTION/END/ABORT synonym completeness rides here*); **S2** cursors (DECLARE/FETCH/MOVE/CLOSE, WITH HOLD) + SQL PREPARE/EXECUTE/DEALLOCATE over F-0's portal store; **S3** LOCK TABLE + advisory locks (the donor's known-hard item; multi-range home = a range-0 lock service — coupled design); **S4** LISTEN/NOTIFY/*UNLISTEN* — commit-time delivery, Engine-level bus, and **cross-gateway delivery via the range-0 topic tail** (the substrate is the bus; multi-range tenants get NOTIFY for free); **S5** SERIALIZABLE (SSI) — relation-granularity SIREAD first, row-granularity after D2; single-range first, **cross-range SSI × ts-transactions is a G-9-coupled design cycle**, stated; **S6** EXPLAIN [ANALYZE] over the interpreter + G-9b planner seam (honest plan shapes, growing with the planner).
**Track P — procedural/tooling (latest):** **P1b** information_schema (after D5); **P2 routines** — CREATE FUNCTION (LANGUAGE sql), DO, *CREATE/ALTER/DROP PROCEDURE, CALL, ALTER/DROP FUNCTION/ROUTINE*; **P3** PL/pgSQL interpreter (pure-Rust; *in-procedure COMMIT/ROLLBACK*) — the program's largest single wave, staged internally; **P4** triggers (row/statement, BEFORE/AFTER/INSTEAD OF with D5) (*event triggers = stretch*); **P5 utility bucket** — VACUUM (maps to the garbage horizon/compact hint), ANALYZE (stats for G-9b), CLUSTER/REINDEX/CHECKPOINT/*ALTER SYSTEM*/*CREATE-ALTER-DROP STATISTICS* as documented no-ops-with-notice or mappings, DISCARD (F-1), the FDW DDL lifecycle completeness (*ALTER FDW/SERVER/FOREIGN TABLE — the one family where support already exists*); **P6 stretch** — CREATE CAST / CREATE AGGREGATE over SQL/PLpgSQL functions.

## Milestones (the product-truth gates)

- **M0 — drivers work:** F-0 + F-1. Gate: parameterized-query smokes across tokio-postgres, sqlx, and one dynamic-language driver, through PgDog in transaction mode; the conformance corpus green through the extended protocol.
- **M1 — pgbench green:** D1 + D2 + D3 + Q5 (pgbench's init uses COPY). Gate: stock `pgbench` initializes and runs — the chapter's long-deferred ambition, now scheduled.
- **M2 — psql usable:** F-2. Gate: `psql` interactive session with working `\d`, `\dt`, `\di`, `\l`, `\du` against a tenant.
- **M3 — ORMs/migrations:** Q1 + D4 + S1 (+ M2). Gate: a migration-tool smoke suite (a Rails-style and a Django-style migration corpus, plus sqlx macros) runs end-to-end.
- **M4 — pg_regress adoption (standing):** progressively vendor applicable portions of PostgreSQL's own regression corpus (PostgreSQL License — compatible) as conformance corpus sources, file-by-file with per-file ratchets; the adoption percentage is a published per-PR number from here to the horizon.
- **M5 — the 190 answered:** `docs/PG_COMPAT_MATRIX.md` shows no `UNDECIDED` row; CI diffs the matrix against the parser's accepted-statement surface so the matrix cannot rot.

## The standing per-cycle rules (every wave's design must answer)

1. **Oracle discipline:** corpus vs pinned `postgres:18`; the quirk is the spec; baseline ratchets in the same reviewed commit.
2. **The sharded/ts-table story:** semantics on G-8/G-9 tables stated and tested (e.g. UNIQUE → global-index dependency; sequences → block allocation; FK across ranges → ts-txns; NOTIFY → range-0 bus; SSI → the named G-9 coupling). "Single-range only, 0A000 on sharded" is an acceptable *stated* answer; silence is not.
3. **The pooler story:** behavior through PgDog transaction mode stated; pooler-baseline deviations recorded with rationale.
4. **The matrix:** every command/feature the wave touches moves from `UNDECIDED`/`ERROR` to its final disposition in `PG_COMPAT_MATRIX.md` in the same commit.

## Risks

- **The F-0 trait widening is a one-way door** — designed once, consumed by COPY/cursors/NOTIFY/params; its cycle gets the extra review weight (and the reserved-variant trick keeps later waves additive).
- **PL/pgSQL is a language implementation** — staged internally (parser → expression bridge → control flow → cursors/exceptions → in-proc txn control), each stage corpus-gated; the wave may split further at its own design cycle.
- **SSI correctness** — model-checked like everything else (SIREAD/pivot detection is a textbook Stateright target), and the cross-range coupling is deferred to its named G-9 cycle rather than half-shipped.
- **Scope creep via "just one more function"** — the matrix plus the between-cycles rule (small scalar functions may land without a chapter decision; anything with a matrix row may not) keeps the program legible.
- **Corpus drift against future PG majors** — the oracle pin advances deliberately (a matrix-reviewed bump, the PgDog-pin idiom).

## Resolved decisions

- Wave map as above (the grounding's eight-point completeness delta folded in); F-0 parameters first; milestones M0–M5; `PG_COMPAT_MATRIX.md` with CI anti-rot; pg_regress progressive adoption.
- Explicit dispositions: 2PC-SQL = stock-default error; one database per tenant; large objects non-goal; extension-statement whitelist; C-bound non-goals named; CAST/AGGREGATE = P6 stretch; event triggers = P4 stretch.
- Standing rules: oracle/ratchet, sharded story, pooler story, matrix update — per cycle, no exceptions.
- G-6's breadth track is absorbed here; G-6 keeps the FDW items and the ratchet process it already owns.
