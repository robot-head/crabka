# The TypeScript SDK — design

**Date:** 2026-07-06
**Status:** Approved
**Type:** Language cycle under the [application-SDK umbrella](2026-07-06-crabka-app-sdk-umbrella-design.md). Implements contract v1 in TypeScript; definition of done = the conformance suite green through the TS adapter.

## Context

The second language after the Go reference, and the highest-DX-value one (the vision doc's BaaS audience). The umbrella fixes everything semantic — the six modules, the error taxonomy, the vector-pinned stubs — so this cycle is transport + idiom + the adapter.

**Runtime target: Node** (serverless functions are Node runtimes). The **browser is explicitly out of scope** for v1: the `Subscribe` RPC is bidi, Connect-in-browser cannot do bidi over fetch/h1, and no gRPC-Web proxy exists — the same constraint MSG-5 recorded. A browser build is a future cycle riding a server-streaming or WebSocket surface, not this one.

## Design Goals

- **Connect-ES stack, no bespoke transport:** `@connectrpc/connect` + `@connectrpc/connect-node` (whose Node http2 transport speaks h2c — required for the bidi `Subscribe` against the gateway listener MSG-5 enables), stubs generated by `protoc-gen-es` via the existing repo-root buf config.
- **Idiomatic surface, identical semantics:** promises + `AsyncIterable` for subscribe; the taxonomy as an `CrabkaError` hierarchy with `UnimplementedError { module, gatedOn }` carrying the umbrella's pinned slugs.
- **The adapter is a thin Node CLI** (`sdks/ts/src/conformance-adapter.ts`): JSON-lines stdio ↔ the SDK, per the harness protocol.

## Non-goals

Browser builds; manual per-offset ack beyond the experimental flag (MSG-3-gated, as everywhere); framework integrations (Next/Hono helpers — later); publishing to npm (packaging exists, publish workflow deferred with the rest of SDK release engineering).

## Architecture

```
sdks/ts/                     (package @crabka/sdk, ESM, Node ≥ 20)
├── package.json / tsconfig.json / vitest.config.ts
├── gen/                     protoc-gen-es output (buf.gen.yaml gains the es plugin block; drift-checked)
├── src/
│   ├── client.ts            createClient({ endpoint, bearerToken?, mtls? }) → { messaging, queues, database, auth, blob }
│   ├── errors.ts            CrabkaError → Transport | Unauthenticated | InvalidArgument | NotFound | ServerError
│   │                        | UnimplementedError{module, gatedOn}
│   ├── messaging.ts         publish / publishEvent (CE mapping shared semantics w/ Go — vector-pinned)
│   │                        subscribe(topics, {group, filter}) → AsyncIterable<InboundMessage>
│   ├── stubs.ts             queues / database / blob → the pinned Unimplemented errors; auth = credential config only
│   └── conformance-adapter.ts
└── test/                    vitest units (CE mapping, error mapping, config)
```

Transport detail: one `createConnectTransport({ httpVersion: "2" })` (h2c to the plaintext gateway); `Subscribe` = the bidi stream, one `SubscribeStart` frame sent, then the response stream surfaced as `AsyncIterable`; iterator `return()`/abort closes the stream.

## Integration

- **`buf.gen.yaml`** — add the `buf.build/bufbuild/es` plugin block, `out: sdks/ts/gen` (drift check extends the existing job).
- **CI prerequisite (named):** `actions/setup-node` does not exist in any workflow — this cycle adds it, plus a `sdk-ts` job: `npm ci && npm run build && vitest run`, then the conformance suite with `--adapter sdks/ts/bin/conformance-adapter`.
- **The umbrella harness is unchanged** — that's the point.

## Testing

Vitest units for the pure parts (CE header mapping incl. never-`ce_datacontenttype`, error-code mapping, config precedence); **the conformance suite is the gate** — all v1 vectors green through the Node adapter against the in-process harness substrate.

## Risks

- **h2c from Node:** `connect-node`'s http2 transport must negotiate cleartext h2 against the gateway's `auto::Builder` listener — verified end-to-end as the cycle's first integration step (the riskiest assumption, same shape as MSG-5's).
- **ESM/CJS packaging friction** — ESM-only, Node ≥ 20; documented, revisit only on real demand.
- **Contract drift** — none possible by construction: the suite pins it.

## Resolved decisions

Node-only v1 (browser deferred with rationale); Connect-ES + `protoc-gen-es` via repo buf config; `AsyncIterable` subscribe; the umbrella taxonomy verbatim; `setup-node` lands with this cycle.
